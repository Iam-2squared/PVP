# 地形・城壁のボクセル試作

2026-10-27。画像の王都配置を土台に、地形と城壁だけを制作したGodot 4.6.3プロジェクト。住宅・王城・NPC・戦闘システムを配置する前の、形と移動の確認用。

## 制作したもの

- 共通0.5mグリッドで形を刻んだ正八角形の城壁。斜辺は段状に表現。
- 厚い段状基礎、控え壁、石の色帯、射撃用の細い開口、胸壁、連続した城壁上の歩廊。
- 8か所の角塔、東西南北の4門楼、門脇の8塔。
- 通行できる段状アーチ、上げた状態の木製格子、青い旗、階段状の青屋根。
- 内側から城壁上へ登る階段。
- 野原、連続する山稜・鞍部、砂丘・砂岩露頭、砂浜・段丘・浅瀬。
- 門から城外へ続く道。一人称歩行、ジャンプ、全体図、タッチ操作。

城内は今後城下町を置くための地形だけとし、現段階では空けている。
半幅128mの王都と、その周辺およそ640m四方を試作。縮尺と初期リスポーン位置は仮。

## 軽量化の方法

- ボクセル1個につきNodeやCubeを作らず、露出する表面だけを生成する。
- 隣接するブロックの内部面を削除し、同色・同方向・同じ陰影条件の面を長方形に結合する。
- 城壁は32m、地形は64mごとの空間区画にまとめ、画面外を描画しない。
- 城壁の局所的な陰影は頂点色に焼き込む。石・屋根・木・旗は一つの材質に頂点色で表現する。
- 地形は0.5m刻みの高さを維持。門・基礎・海岸付近は1m間隔、遠方の広域山稜・砂丘は2m間隔で高さを採る。
- 地形のリアルタイム影の生成は省き、城壁の影を受け取る。城壁は一つの太陽光で影を落とす。
- 地形と衝突判定は制作時に生成し、圧縮済みシーンとして保存。実行時は読み込むだけ。
- テクスチャ画像や有料モデルには依存しない。日本語フォントも必要文字だけを収録。

生成済みデータの実測値は `generated/world_metrics.json` に保存。
現在の目安は、城壁493,158ボクセルを44区画・194,954三角形、陸地を75区画・104,648三角形にまとめたもの。海面は2,532三角形。このほかに少数の草・岩のブロックを加えている。圧縮シーンは約4.47MB。

制作環境の実描画では、南門の一人称視点192 draw calls、俯瞰視点245 draw callsを確認。影などの描画も含む値で、視点・設定によって変化する。スマートフォン実機のFPS・メモリ使用量は未計測。

## 起動と操作

Godot 4.6.3で `project.godot` をインポートしF5。追加ライブラリやBlenderは起動に不要。

| 操作 | 入力 |
|---|---|
| 移動 | WASD / 左タッチスティック |
| 視点 | 画面クリック後マウス / 右側の空白をドラッグ |
| 走る | Shift |
| 跳ぶ | Space / ジャンプボタン |
| 全体図 | M / 右上の全体図ボタン |
| マウス解除 | Esc |
| 仮の開始位置へ戻る | R |
| 開発用の統計表示 | F3 |

0.5mまでの段差は歩いて登れる。海へ落ちると仮の開始位置へ戻る。

## 造形を編集する場所

| ファイル | 内容 |
|---|---|
| `scripts/voxel/walls.gd` | 城壁・塔・門・胸壁・階段のブロック配置 |
| `scripts/voxel/terrain.gd` | 山稜・野原・砂漠・海岸と地形の結合 |
| `scripts/voxel/volume.gd` | 制作時のボクセルデータ |
| `scripts/voxel/mesher.gd` | 露出面の結合・頂点色・陰影・衝突メッシュ |
| `scripts/voxel/factory.gd` | 地形と城壁の組み立て |
| `scripts/voxel_preview.gd` | 生成済みシーンの読み込みと光・空 |
| `scripts/player_controller.gd` | 一人称操作と段差の移動 |
| `scripts/hud.gd` | 探索UI |

生成ロジックを変更したら、プロジェクトフォルダーで再生成する。

```sh
godot --headless --path . --script res://tools/bake_voxel_world.gd
```

通常は同梱の `generated/kingdom.scn` を開くため、再生成は不要。編集前の古い形が表示される場合は、再生成後にF5する。

## 検証

```sh
godot --headless --path . --script res://tools/test_voxel_world.gd
```

実際の生成済みシーンに対し、八角形、地面、門、壁、城壁上、移動、階段、海からの復帰、描画用の形状数を検証する。

統合検証35項目を通過。Chromiumのデスクトップ1280×720とモバイル横844×390でも、Web版の起動・実3D描画・移動・全体図・タッチ操作を確認し、致命的なJS/GDScriptエラーは0。モバイル寸法のエミュレーションであり、実機の速度検証とは区別する。再現用は `tools/browser_smoke.py`（Python Playwrightが必要）。

実レンダリングの画像を撮るには、画面表示が可能な環境で以下を実行する。

```sh
godot --path . --script res://tools/capture_preview.gd -- --overview --hide-hud --output=/tmp/voxel-overview.png
```

## ブラウザ版

同じバージョンのGodot Web export templateを導入してから、プロジェクトフォルダーで実行する。

```sh
mkdir -p build/web
godot --headless --path . --export-release Web build/web/index.html
python3 tools/serve_preview.py --directory build/web --port 8080
```

`http://127.0.0.1:8080` を開く。HTMLの直接ダブルクリックではなくHTTPで配信する。
同一LANの端末から試す場合は、サーバー起動時に `--bind 0.0.0.0` を加え、PCのLANアドレスとポートへアクセスする。

`tools/download_web_templates.py` は公式テンプレートのWeb部分だけを取得する補助ツール。対象Godotバージョンを確認して使用する。

## 外部3Dツール向けの書き出し

```sh
godot --path . --script res://tools/export_model.gd -- --output=res://build/selesia-voxel-terrain.glb
```

GLBは造形確認・外部編集向けの出力。衝突判定や歩行操作はGodotプロジェクト側に含まれる。GLBを変更しても生成ロジックへ自動反映はされない。
